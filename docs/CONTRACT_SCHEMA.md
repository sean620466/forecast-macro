# Prediction Market Contract Schema

## 목적

서로 다른 플랫폼의 계약을 모델 결과와 비교하기 전에 동일한 결과공간과 시점으로 정규화한다.

## Fed 기본 결과공간

- `hike`
- `hold`
- `cut_25`
- `cut_50_plus`

플랫폼 계약 정의가 다르면 강제로 합치지 않고 별도 mapping을 기록한다.

## 필수 필드

- 플랫폼 및 contract ID
- 회의/결과 결정시각
- 시장가격 관측시각
- 계약 원문과 해석 버전
- 상호배타적 outcome 목록
- 각 outcome의 bid/ask 또는 체결가
- 수수료 규칙

## 가격 처리 (D-015)

상호배타 구간 계약의 YES 호가에서 확률을 만든다.

1. 완전성: `Σbid ≤ 1 ≤ Σask` (허용 오차 0.01). 매수호가 합이 1을 넘으면 결과가 겹치는 것이고, 매도호가 합이 1에 못 미치면 결과가 빠진 것이다.
2. 폭: `Σask − Σbid ≤ 0.35`. 넘으면 호가가 너무 넓어 가격을 매길 수 없다.
3. 확률: 각 구간의 `[bid, ask]`를 범위로 보존한다. 점추정은 mid에서 초과분 `Σmid − 1`을 스프레드 비례로 덜어낸 값이다. 1번 조건이 성립하면 점추정은 항상 `[bid, ask]` 안에 있고 합이 정확히 1이다.

이전 규칙(mid 합 ±5%, D-010)은 꼬리 구간의 넓은 스프레드 때문에 정상 시장(실측 mid 합 1.14, bid 합 0.995)을 거부했다. 동일 시각 관측, 완전한 결과 집합, 구간별 스프레드 상한(0.10)과 최소 호가량은 그대로 요구한다. 플랫폼별 거래수수료는 이후 별도 비용 모델에서 edge와 비교한다.

## 누적 임계값 사다리 (Kalshi, 과제 12)

Kalshi 금리 계약은 "상단이 F%를 초과하는가"의 YES 시장이 0.25%p 간격으로 나열된다. 이는 상호배타 구간이 아니라 누적분포다.
`normalize_threshold_ladder`가 연속성(0.25 간격, 빈 rung 없음)과 단조성(높은 F의 YES가 낮은 F보다 높지 않음, 허용 0.02)을
검사한 뒤 인접 rung 차이로 배타 구간 확률과 `[bid, ask]` 범위를 만든다. 구간 라벨은 `le_2.75`, `3.00`, …, `5.25`, `gt_5.25`
형식이며 숫자 라벨은 "회의 후 상단 = 그 값"을 뜻한다.
